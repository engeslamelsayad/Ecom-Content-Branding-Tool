## 2. القرارات المعمارية

### أ. الـ Skills تفضل Markdown — الأداة بتقراها وقت التشغيل

أهم قرار في المشروع. الاستراتيچية مش منسوخة في كود.

```
تعدّل ملف .md على GitHub → redeploy → الأداة بقت أذكى
                                       (من غير سطر كود واحد)
```

وتقدر تضيف skill رابعة (SEO، Retention، Email) بمجرد رفع فولدر جديد.

### ب. Progressive Disclosure + Prompt Caching

مش بنبعت الـ 3,700 سطر كل مرة. كل موديول بيحمّل `SKILL.md` بتاعه + الـ references اللي محتاجها **بس**. والبرومبت مرتّب عشان الكاش (الكاش بيطابق البادئة — أي بايت بيتحرك بيلغي كل اللي وراه):

```
system[0] = نص الـ skill          ← ثابت لكل موديول   (cached)
system[1] = القواعد + Brand Brain  ← ثابت لكل براند    (cached)
messages  = الطلب نفسه             ← متغيّر، مش متكاش
```

### ج. Brand Brain — الذاكرة الدائمة

**المشكلة:** الـ 3 skills كلهم بيقولوا حرفيًا *"Never skip the intake questionnaire"*. في داشبورد ده معناه إنك تجاوب على نفس الـ 8 أسئلة كل مرة تفتح موديول. بعد تلات مرات هتبطل تستخدمها.

**الحل:** طبقة ذاكرة لكل براند:

```
Brand ──┬── Identity      (الاسم · المجال · السوق · اللهجة)
        ├── Products      (السعر · التكلفة · الـ USP)
        ├── Avatars       (الرغبة · الخوف · الـ Trigger · الاعتراضات)
        ├── Competitors   (الرسالة · السعر · نقطة الضعف)
        ├── VoC Bank      (كلام عملاء حقيقي، بيدخل الكوبي بالحرف)
        └── Core          (مخرجات الموديولات السابقة)
```

كل موديول **بيقرأ** من الـ Brain. و11 موديول مخرجاتهم **بتدخل** الـ Brain — **بعد ما تعتمدها** (التفاصيل في القسم 12). تعمل `/heart` وتعتمده → القيم والأركيتايب يتخزنوا → أي موديول بعده يطلع متسق معاهم.

> ⚠️ في النسخة الأولى كانت المخرجات بتدخل الـ Brain لوحدها. ده اتغيّر في كوميت `ff626ba`: المخرج دلوقتي مسودّة لحد ما يتعتمد.

## 4. المساعد الذكي في الفورمات

**النقطة الحرجة:** خطة مبنية على إيراد متخيّل ومنافسين موهومين **بتحلل خيال — بثقة**. ده أسوأ من فورم فاضي.

فكل حقل بياخد سياسة:

| السياسة | العدد | المسموح | أمثلة |
|---|---|---|---|
| 🔒 `none` | 20 | **بيرفض** ويقولك تحط إيه | الميزانية · الإيراد · الهامش · الريفيوهات · روابطك · ذوقك |
| 📥 `extract` | 43 | بيسحبها من الـ Brain أو من مصدر انت دّيته | المنتج · اللهجة · الأسواق · العرض |
| ✍️ `draft` | 52 | بيقترح مسودّة من السياق | المشكلة اللي بتحلها · الإحساس المطلوب · صياغة الهدف |

**القاعدة متطبّقة في الكود مش في البرومبت.** ✅ *مُختبر:* خلّينا الموديل يخترع رقم إيراد بثقة `high` — السيرفر شال القيمة وحوّلها لـ `needs_user` قبل ما توصل للمتصفح، ورمى حقل مكنش مطلوب.

**شكل الاقتراح:** القيمة بتنزل في الحقل نفسه (تعدّلها على طول)، وتحتها درجة ثقة + مصدر الاقتراح + زرار رجوع. أول ما تعدّل، العلامة تختفي — بقت قيمتك.

## 5. التهيئة السريعة من رابط الموقع

في **نفس شاشة إنشاء البراند**:

```
+ براند جديد
  🌐 عندك موقع؟  https://yourstore.com  [🪄 اقرا]
        ↓
  Chromium يقرا لحد 5 صفحات (مش الرئيسية بس)
        ↓
  الاسم · الوصف · المجال · اللهجة  ← اتملوا
  + المنتجات والأسعار · المنافسين · الريفيوهات · الأفاتارات
        ↓
  تشيل الغلط → [أنشئ البراند واحفظ المحدّد]
```

**ترتيب الصفحات:** صفحات المنتجات والريفيوهات الأول (الأسعار والريفيوهات الحقيقية مش في الهوم بيدج)، بعدين "من نحن" والـ FAQ. نفس الدومين بس.

**الصندوق الأصفر** بيقولك إيه الناقص اللي لازم تحطه بنفسك (تكلفة المنتج، أرقام الأداء، باقي المنافسين).

### 🔒 ثغرة أمنية اتقفلت

السيرفر بقى بيفتح روابط اليوزر — دي **SSRF**. `assert_public_url()` بيفحص قبل الفتح **وبعد أي redirect**:

| الرابط | النتيجة |
|---|---|
| `http://169.254.169.254/` (بيانات السحابة) | ✅ اترفض |
| `http://localhost:8000/` · `http://127.0.0.1/` · `http://[::1]/` | ✅ اترفض |
| `https://10.0.0.5/` | ✅ اترفض |
| `file:///etc/passwd` | ✅ اترفض |
| `https://example.com` | ✅ اتقبل |

كلهم متأكد منهم **من خلال الـ API نفسه**.

## 6. المشاكل اللي حصلت وإزاي اتحلت

### ❌ 1. فشل بناء الـ Docker على Railway

```
BEWARE: your OS is not officially supported by Playwright;
        installing dependencies for ubuntu20.04-x64 as a fallback.
E: Package 'ttf-unifont' has no installation candidate
```

**السبب:** `python:3.12-slim` **بقى Debian 13 (trixie)** مش bookworm. Playwright 1.49 معندهوش قائمة اعتماديات لـ trixie → وقع على fallback بتاع ubuntu20.04 اللي فيه حزمتين خطوط مش موجودين في Debian.

**التحقق:** فتحت جدول Playwright الداخلي — `debian12` موجود (7 مواضع)، `trixie` **صفر**، و`ttf-unifont` في بلوك ubuntu20.04 بالظبط.

**الحل:** `FROM python:3.12-slim-bookworm` + تعليق يشرح ليه عشان محدش "ينضّفه".

---

### ❌ 2. `SECRET_KEY` كان إعداد ميت

كتبت في الـ README إنه مطلوب — **ومحدش كان بيقراه**. نظام الجلسات مابيحتاجوش:

| الطريقة اللي بتحتاجه | اللي عملناه |
|---|---|
| كوكي بتحمل بيانات **موقّعة** | كوكي بتحمل **توكن عشوائي** |
| لو المفتاح اتسرب → أي حد يزوّر جلسة | مفيش مفتاح يتسرب أصلاً |

اتشال هو ومكتبة `itsdangerous` اللي كانت مضافة عشانه.

---

### ❌ 3. صفحة بيضا بعد تسجيل الدخول (باج مني)

التعديل اللي كان المفروض يضيف `Globe, Wand2` للـ imports **مانفّذش**، وماتحققتش — اكتفيت إن البيلد نجح.

**الخطورة:** Vite مابيفشلش على اسم مش متعرّف — بيفترض إنه متغير عام ويبني عادي.

```
Shell بيترندر → NewBrandModal بيترندر (حتى والنافذة مقفولة،
لأن الـ JSX children بتتبني قبل ما تتبعت) → <Globe/> → ReferenceError
→ React بيفضّي الشجرة → صفحة بيضا
```

**إزاي اتعرف:** اللوج بتاعك كان بيقول كل حاجة —
```
POST /api/auth/login  200 OK
(مفيش /api/catalog ... مفيش حاجة خالص)
```
الوقوع حصل **أثناء الرندر**، قبل أي طلب. شغّلنا نسخة محلية بنفس البيلد المنشور وفتحناها بـ Chromium → نفس البصمة بالحرف.

**المنع:** ربطنا ESLint بالبيلد. وهنا درس مهم — أول ما ضفنا `no-undef` **جربنا نرجّع الباج للتأكد** وطلع الـ lint **خرج بـ 0**! لأن قواعد ESLint الأساسية مابتعتبرش اسم الكمبوننت في الـ JSX مرجع متغير. فضفنا `react/jsx-no-undef`:

```
src/App.jsx
  350:14  error  'Globe' is not defined  react/jsx-no-undef   exit=1
```

دلوقتي `npm run build` = `eslint src && vite build` — نسيان import بيفشّل البناء بدل ما يطلع صفحة بيضا.

## 12. تحديث: إزاي المخرجات بتأثر على اللي بعدها

### الإجابة

**الـ Brand Brain: أيوه، بيأثر على كل مخرج.** **المكتبة: لأ**، الأداة مش بتقراها. بس فيه
